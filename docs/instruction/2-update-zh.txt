升级已安装的固件


从 1.x 版本升级到 1.4

1.4 系列版本基于新的 OpenWrt 和新的内核。升级方法和平时一样，设置会保留。

有一件事最好提前知道。你自己安装的软件包会在升级后重新安装一次，这次是为新内核安装的。路由器会自动完成，但需要能上网。

哪些版本可以升级

1.4.x、1.3.0、1.3.1 以及 1.2.3 到 1.2.7 可以直接升级。
如果你的 /overlay 在 USB 磁盘上，请直接安装 1.4.4 或更新的版本。更新到 1.4.3 后路由器会停在内部分区上，要用 reboot 命令手动重启才能恢复。
1.0 到 1.2.2 请先阅读本文件最后的"如果你的版本低于 1.2.3"。升级前需要运行一条命令。

升级之前

1. 保存设置。打开 系统, 备份与更新，点击"生成备份"。文件会保存在你的电脑上。

2. 如果你自己装过软件包，把软件包列表保存下来。下面这条命令会把列表打印出来。

cat /etc/apk/world

列表里也有固件自带的软件包，你装的那些也在其中。把它复制到别的地方保存。一般软件包会自己装回来，但如果新的软件源里缺了某个包，你就知道要手动装哪个。

3. 确认网络正常。升级需要几分钟，这段时间网络会断开。

怎样升级

最简单的方法是用 系统, 固件更新 页面。它会找到新版本并显示更新内容。点一个按钮，它就会下载镜像、检查镜像，然后升级路由器并保留设置。

在命令行里也可以这样做。

be7000-update check
be7000-update apply

也可以用 sysupgrade.bin 手动升级，见下面的"手动升级"。

第一次启动时会发生什么

第一次启动比平时慢，最多要几分钟。在指示灯变成白色常亮之前不要断电。

如果你的设置放在 USB 硬盘上，路由器会自己重启一次。这是正常的。

网络连上以后，路由器会安装你的软件包。可以在 状态, 系统日志 里查看，看带有 be7000-romsync 的那几行。如果新的软件源里没有某个包，它会被跳过，其他的照常安装。被跳过的包会列在 "not in the feed of this image, dropped" 这一行里。

5 GHz 模式保持原样。新的 MLO 模式可以以后再打开。

升级时不会导入原厂设置。只有第一次从原厂固件安装时才会导入，你现有的设置保持不变。

升级后检查什么

状态, 概览 应该显示你安装的版本，并且网络正常。
网络, 无线 应该显示两个网络。如果国家代码是 RU，会有一条 Wi-Fi 7 已关闭的提示。点旁边的按钮，5 GHz 会改成 US，Wi-Fi 7 就又能用了。
系统, 软件包 里应该又能看到你的软件包。如果缺了什么，对照你保存的列表手动安装。

如果出了问题

打开 状态, 系统日志，把日志发到 4PDA 的帖子里。

也可以用同样的方法回到 1.3.1，使用 1.3.1 发布页里的 sysupgrade.bin。如果之后设置表现异常，就恢复升级前保存的备份文件。

槽位 页面在这里帮不上忙。另一个槽位里是原厂固件，不是之前版本的 Beam WRT。


常规升级

通过网页界面

从 1.2.6 开始有 系统, 固件更新 页面。它会在 GitHub 上检查有没有新版本，并显示新版本的内容。点一个按钮，它就会下载镜像、检查校验值，然后升级路由器并保留设置。在命令行里用 be7000-update check 和 be7000-update apply 也是一样的。在 1.4.0 之前，这个菜单项可能显示为俄文 "Обновление сборки"。 有新版本时路由器会自己提示，每天检查一次 GitHub，在顶部栏和 状态, 概览 页面显示提示。这项检查可以在同一页面关闭。

如果你还没有这个页面，可以从软件源安装，命令是 apk add luci-app-be7000-update。这需要 1.2.5 或更新的版本。固件版本写在 /etc/be7000-release 里。没有这个文件的话，固件会被当成自己编译的版本，不会提示升级。

手动升级

从发布页下载 openwrt-qualcommbe-ipq95xx-xiaomi_be7000-squashfs-sysupgrade.bin，然后用下面的命令升级路由器。如果你的路由器地址不同，换成你自己的地址。

scp -O openwrt-qualcommbe-ipq95xx-xiaomi_be7000-squashfs-sysupgrade.bin root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sysupgrade -v /tmp/openwrt-qualcommbe-ipq95xx-xiaomi_be7000-squashfs-sysupgrade.bin"

升级会写入路由器当前启动的槽位。另一个槽位里的原厂固件不受影响。设置、软件包和已启用的服务都会自动保留下来。


如果你的版本低于 1.2.3

在下面找到你的版本。

1.0、1.1、1.2、1.2.1 和 1.2.2 版本

引导程序会记录启动次数，而这些版本从来不会把计数清零。第七次启动后，路由器会自己切换到原厂固件。Beam WRT 还在它的槽位里，但看起来就像路由器回到了小米固件。升级前请通过 SSH 把计数清零。

fw_setenv flag_try_sys1_failed 0 && fw_setenv flag_try_sys2_failed 0

可以用 fw_printenv flag_try_sys1_failed flag_try_sys2_failed 检查，两个值都必须是 0。从 1.2.3 开始，固件会自己清零。如果路由器已经回到了原厂固件，也没有丢失任何东西。按照 1-install-zh.txt 再运行一次 install-from-stock.sh 就行。

槽位 0 上的 1.0 和 1.1 版本

在这两个版本里，升级总是写入槽位 1，也就是覆盖原厂固件。新镜像修复了这个问题，但这一次升级仍然按旧规则进行。如果你还需要原厂固件，升级前先备份一份，方法见 1-install-zh.txt 的第 1 步。

1.2 和 1.2.1 版本

这次升级时两个无线可能都会关闭。如果 Wi-Fi 没了，到 网络, 无线 里重新打开。以后不会再出现这种情况。
