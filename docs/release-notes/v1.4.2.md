Beam WRT 1.4.2. Zapret Manager и исправления обновления.

Что добавлено

- На странице Сервисы, Дополнения появился Zapret Manager. Сначала ставится только сам менеджер. Zapret и другие способы обхода не запускаются, пока пользователь сам не выберет нужный вариант.
- Для Beam WRT собираются Zapret, Zapret2, ByeDPI, NetShift, sing-box, hev-socks5-tunnel и интерфейс AmneziaWG. Пакеты лежат в нашем фиде и проверяются обычной подписью APK.
- Терминальная команда `zms` запускает закреплённую копию менеджера через Bash. Она больше не заменяет себя загрузчиком свежего скрипта из интернета. Обновление менеджера тоже идёт через фид Beam WRT.

Что исправлено

- После обновления прошивки внешний `/overlay` мог не примонтироваться, хотя USB-диск был на месте и оставался в настройках. Теперь служба видит такой запуск, один раз перезагружает роутер и продолжает работу с выбранного диска. Маркер повторной попытки не даёт получить цикл перезагрузок.
- Восстановление пакетов после обновления могло остановиться из-за DNS. Настройки Hybrid Failover уже направляли запросы на `127.0.0.42`, но сам пакет ещё не успевал установиться. На время восстановления включается прямой DNS. Когда Hybrid Failover запускается, прежние настройки возвращаются.
- Из списка репозиториев убран официальный target snapshot OpenWrt. Он меняется независимо от Beam WRT и содержит модули для другого ABI ядра. Теперь модули ядра берутся только из подходящего фида Beam WRT.

Обновление с 1.4.1 обычное. Настройки сохраняются. Если `/overlay` находится на USB-диске, после первого запуска роутер может сам перезагрузиться ещё один раз.

Beam WRT 1.4.2. Zapret Manager and update fixes.

What was added

- Zapret Manager is now available on Services, Add-ons. Only the manager is installed at first. Zapret and other bypass methods stay off until the user selects one.
- Beam WRT builds Zapret, Zapret2, ByeDPI, NetShift, sing-box, hev-socks5-tunnel and the AmneziaWG interface. The packages come from our feed and pass the normal APK signature check.
- The `zms` command runs the pinned manager copy through Bash. It no longer replaces itself with a downloader for the latest Internet script. Manager updates also come through the Beam WRT feed.

What was fixed

- An external `/overlay` could stay unmounted after a firmware update even though the USB disk was present and still configured. The service now detects this boot, restarts the router once and continues from the selected disk. A retry marker prevents a reboot loop.
- Package recovery after an update could stop because of DNS. Hybrid Failover settings already sent requests to `127.0.0.42`, while its package had not been restored yet. Direct DNS is used during recovery. The previous settings return when Hybrid Failover starts.
- The official OpenWrt target snapshot was removed from the repository list. It moves independently from Beam WRT and carries modules for a different kernel ABI. Kernel modules now come only from the matching Beam WRT feed.

Updating from 1.4.1 is unchanged and keeps the settings. A router using a USB disk for `/overlay` may restart itself once more after the first boot.

Beam WRT 1.4.2。新增 Zapret Manager，并修复更新后的恢复问题。

新增内容

- 服务，扩展程序 页面新增了 Zapret Manager。初次安装只会安装管理器本身。Zapret 和其他绕过方案保持关闭，直到用户自己选择。
- Beam WRT 会构建 Zapret、Zapret2、ByeDPI、NetShift、sing-box、hev-socks5-tunnel 和 AmneziaWG 界面。这些软件包来自 Beam WRT 软件源，并通过正常的 APK 签名检查。
- `zms` 命令通过 Bash 运行仓库中固定的管理器版本，不再把自己替换成从网络下载最新脚本的启动器。管理器更新也从 Beam WRT 软件源安装。

修复内容

- 固件更新后，即使 USB 磁盘仍然存在并保留在设置中，外部 `/overlay` 也可能没有挂载。现在系统会识别这种启动，只额外重启一次，然后从用户选择的磁盘继续运行。重试标记可以防止重启循环。
- 更新后恢复软件包时，DNS 可能中断恢复过程。Hybrid Failover 的设置已经把请求发往 `127.0.0.42`，但程序包本身还没有恢复。恢复期间系统会临时使用直连 DNS。Hybrid Failover 启动后会恢复原来的设置。
- 软件源列表中删除了官方 OpenWrt target snapshot。它的更新节奏与 Beam WRT 不同，其中的模块对应另一个内核 ABI。现在内核模块只从匹配的 Beam WRT 软件源安装。

从 1.4.1 更新的方法不变，设置会保留。如果 `/overlay` 位于 USB 磁盘上，第一次启动后路由器可能会再自动重启一次。
