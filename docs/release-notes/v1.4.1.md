Beam WRT 1.4.1. Исправления MLO, обновления, дополнений и Docker.

Это выпуск с исправлениями найденных после 1.4.0 ошибок.

Что исправлено

- Верхнее звено MLO больше не запускает сканирование в момент создания сети. Раньше радиомодуль мог перестать отвечать, после чего роутер переходил в режим двух отдельных радио.
- Если одно из звеньев не поднялось с первого раза, прошивка повторяет запуск после восстановления радиомодуля. Временный сбой больше не меняет сохранённый режим с MLO на два радио.
- LuCI ждёт настоящее завершение переключения. Краткая потеря связи во время перезапуска 5 ГГц больше не показывается как ошибка, если выбранный режим успешно включился.
- Страница беспроводных сетей правильно показывает сеть MLO, связанную сразу с двумя радио. Служебные отключённые копии сетей скрыты, для нижнего радио видны его канал и ширина, а защита подписана как WPA2/WPA3 SAE (MLO).
- В блоке Режим 5 ГГц оба звена MLO теперь показываются активными со своими каналами и шириной.
- На странице Статус, Обзор сеть MLO больше не теряется у нижнего радио. Оба радио показывают свои каналы, а служебные копии сетей не попадают в список.
- Страница Обновление сборки правильно читает многострочное описание релиза, даже если после переноса строки есть кавычки. Описание 1.4.0 также приведено к виду, который понимает старая версия страницы.
- Страница обновления и команда `be7000-update` больше не принимают отдельный релиз темы Nimbus за новую прошивку. Проверка выбирает только релиз Beam WRT, в котором есть образ sysupgrade и файл контрольных сумм.
- Установка Hybrid Failover со страницы Дополнения снова работает. APK сначала скачиваются во временный каталог и проверяются, только потом начинается установка. После установки `rpcd` запускается снова, поэтому LuCI не остаётся без RPC.
- Пакеты Hybrid Failover и индекс фида подписываются одним ключом. Workflow проверяет подпись каждого APK перед публикацией. Из имён файлов убран архитектурный суффикс, из-за которого `apk` получал 404.
- Перед сменой каталога Docker скрипт пробует создать в нём слой OverlayFS. Неподходящая файловая система больше не записывается в `data_root`. Вместо сломанного Docker пользователь сразу получает понятную ошибку.
- Сообщения `be7000-docker` теперь есть на русском, английском и китайском. Язык берётся из LuCI.

Обновление с 1.4.0 обычное. Можно использовать страницу Система, Обновление сборки или sysupgrade. Настройки сохраняются.

Beam WRT 1.4.1. Fixes for MLO, updates, add-ons and Docker.

This release fixes problems found after 1.4.0.

What is fixed

- The upper MLO link no longer starts a scan while the network is being created. That scan could make the radio firmware stop responding and force the router back to two separate radios.
- If one link does not start on the first attempt, the firmware tries again after the radio recovers. A temporary failure no longer changes the saved mode from MLO to two radios.
- LuCI now waits for the switch to finish. A short loss of connection while 5 GHz restarts is no longer reported as a failure when the selected mode comes up successfully.
- The Wireless page now handles one MLO network attached to two radios correctly. Parked network copies are hidden, the lower radio shows its own channel and width, and security is shown as WPA2/WPA3 SAE (MLO).
- The 5 GHz mode block now shows both MLO links as active, each with its own channel and width.
- Status, Overview no longer loses the MLO network on the lower radio. Both radios show their own channels, and parked network copies are left out.
- The Build update page reads multiline release notes correctly, including quotes after a line break. The 1.4.0 notes were also adjusted for the older version of the page.
- The update page and `be7000-update` no longer treat a separate Nimbus theme release as new firmware. The check only selects a Beam WRT release that contains a sysupgrade image and checksum file.
- Hybrid Failover installs from the Add-ons page again. APKs are downloaded to a temporary directory and checked before installation starts. `rpcd` is started again afterwards, so LuCI does not lose RPC.
- Hybrid Failover packages and the feed index use the same signing key. The workflow verifies every APK before publishing it. The architecture suffix that made `apk` request missing filenames was removed.
- Before changing the Docker directory, the script tries to create an OverlayFS layer there. An incompatible filesystem is no longer written to `data_root`. The user gets a clear error instead of a broken Docker setup.
- `be7000-docker` messages are now available in Russian, English and Chinese. The script follows the language selected in LuCI.

Updating from 1.4.0 is unchanged. Use System, Build update or sysupgrade. Settings are kept.

Beam WRT 1.4.1。修复 MLO、固件更新、扩展程序和 Docker 的问题。

这个版本修复了 1.4.0 发布后发现的问题。

修复内容

- 创建 MLO 网络时，高频段链路不再启动扫描。以前这个扫描可能让射频固件停止响应，路由器随后会退回双射频模式。
- 如果其中一条链路第一次没有启动，射频恢复后会再尝试一次。临时故障不会再把保存的模式从 MLO 改成双射频。
- LuCI 现在会等待切换真正完成。5 GHz 重启时的短暂断线不再被误报为失败，只要所选模式最后正常启动即可。
- 无线 页面现在能正确显示同时绑定到两个射频的 MLO 网络。备用的已禁用网络会隐藏，低频段射频会显示自己的信道和带宽，加密方式显示为 WPA2/WPA3 SAE (MLO)。
- 5 GHz 模式 区块现在会把两条 MLO 链路都显示为已启用，并分别显示信道和带宽。
- 状态, 概览 页面不会再丢失低频段射频上的 MLO 网络。两个射频都会显示自己的信道，备用网络不会出现在列表里。
- 固件更新 页面现在能正确读取多行发布说明，包括换行后的引号。1.4.0 的发布说明也改成了旧版页面可以读取的格式。
- 固件更新 页面和 `be7000-update` 不会再把单独发布的 Nimbus 主题当成新固件。检查时只会选择同时包含 sysupgrade 镜像和校验文件的 Beam WRT 版本。
- Hybrid Failover 又可以从 扩展程序 页面安装了。APK 会先下载到临时目录并完成检查，然后才开始安装。安装后会重新启动 `rpcd`，LuCI 不会失去 RPC。
- Hybrid Failover 软件包和软件源索引使用同一个签名密钥。workflow 会在发布前验证每一个 APK。文件名中的架构后缀已经删除，`apk` 不会再请求不存在的文件。
- 修改 Docker 数据目录之前，脚本会先测试该目录能否创建 OverlayFS 层。不兼容的文件系统不会写入 `data_root`，用户会直接看到错误，不会留下无法启动的 Docker。
- `be7000-docker` 的消息现在有俄文、英文和中文，并跟随 LuCI 中选择的语言。

从 1.4.0 更新的方法不变。可以使用 系统, 固件更新 页面或 sysupgrade，设置会保留。
