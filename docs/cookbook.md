# Рецепты

[English](cookbook.en.md) · [中文](cookbook.zh.md)

Здесь готовые рецепты для частых задач. Команды выполняются по SSH на роутере (`ssh root@192.168.1.1`). Пакеты ставятся из фида сборки, поэтому роутеру нужен интернет. Если что-то не получилось, пришлите вывод команды в тему на 4PDA или в issues.

## USB-модем LTE или 5G

Большинству современных модемов хватает ModemManager и драйверов QMI, MBIM и NCM.

```
apk update
apk add modemmanager luci-proto-modemmanager kmod-usb-net-qmi-wwan kmod-usb-net-cdc-mbim kmod-usb-net-cdc-ncm kmod-usb-serial-option
```

Подключите модем, подождите полминуты и проверьте, что система его видит.

```
mmcli -L
```

Потом в LuCI откройте Сеть, Интерфейсы и нажмите "Добавить". Выберите протокол ModemManager, устройство модема и впишите APN оператора. Зону межсетевого экрана поставьте wan. Модемам Huawei, которые работают по NCM, нужен ещё пакет `kmod-usb-net-huawei-cdc-ncm`.

## Интернет с телефона по USB

Android. Новые телефоны раздают интернет по NCM, старые по RNDIS, поэтому поставьте оба драйвера.

```
apk update
apk add kmod-usb-net-cdc-ncm kmod-usb-net-rndis
```

iPhone. Нужен драйвер ipheth и служба usbmuxd, которая договаривается с телефоном.

```
apk update
apk add kmod-usb-net-ipheth usbmuxd
/etc/init.d/usbmuxd enable
/etc/init.d/usbmuxd start
```

На iPhone подтвердите "Доверять этому компьютеру" и включите режим модема.

Подключите телефон и посмотрите, какой интерфейс появился.

```
dmesg | tail -20
```

Обычно это `usb0` или `eth` с новым номером. В LuCI откройте Сеть, Интерфейсы и нажмите "Добавить". Выберите протокол DHCP-клиент, это устройство и зону wan.

## Docker

Образы Docker не помещаются во встроенную память, нужен USB-диск. Подключите его, отформатируйте и смонтируйте, как описано в [storage.md](storage.md). Потом выполните команду ниже.

```
be7000-docker setup
```

Скрипт сам найдёт смонтированный диск со свободным местом и перенесёт туда данные Docker. Заодно он ставит Dockerman, страницу для контейнеров, образов и сетей. Готовые наборы контейнеров запускаются на странице Службы, "Docker: стеки".

### Контейнеры без интернета

Если qBittorrent ничего не качает, другой контейнер не может выйти в сеть, а веб-интерфейс контейнера не открывается из локальной сети, дело в файрволе. Docker создаёт для своих контейнеров отдельную зону docker, но файрвол роутера по умолчанию ничего не пересылает между зонами. Нужны две пересылки, из docker в wan для выхода в интернет и из lan в docker для доступа к опубликованным портам, и в самой зоне должен быть указан мост docker0. Без этого файрвол не отправляет пакеты контейнеров в зону и выбрасывает их, хотя обе пересылки есть. Мосты пользовательских сетей и стеков добавляются в зону автоматически.

Установка командой be7000-docker setup делает это сама. Если Docker поставлен раньше, выполните команду ниже или нажмите кнопку "Разрешить" на странице Службы, "Docker: стеки".

```
be7000-docker firewall
```

Вручную то же самое делается так, это работает на любой версии. Зона docker должна уже существовать, то есть Docker должен был хотя бы раз запуститься.

```
uci set firewall.docker_wan=forwarding
uci set firewall.docker_wan.src='docker'
uci set firewall.docker_wan.dest='wan'
uci set firewall.docker_lan=forwarding
uci set firewall.docker_lan.src='lan'
uci set firewall.docker_lan.dest='docker'
uci add_list firewall.docker.device='docker0'
uci commit firewall
/etc/init.d/firewall restart
```

Если после этого пересылок нет, а зоны docker в `uci show firewall` не видно, остановите Docker и создайте её штатной командой.

```
/etc/init.d/dockerd stop
/etc/init.d/dockerd uciadd
/etc/init.d/dockerd start
```

Если контейнер всё равно не выходит в сеть, команда `be7000-docker diag` выводит зоны и правила файрвола, интерфейсы и состояние dockerd. Её вывод удобно приложить к сообщению об ошибке.

Hybrid Failover последних версий ведёт контейнеры так же, как остальные устройства сети, мосты Docker он подхватывает сам. Если стоит старая версия, команда `be7000-docker firewall` прописывает контейнерам публичные DNS-серверы, иначе они получали бы от роутера служебные адреса Hybrid Failover и не могли бы к ним подключиться. Без Hybrid Failover DNS не меняется.

## Режимы 5 ГГц

Режим выбирается в блоке "Режим 5 ГГц" вверху страницы Сеть, Беспроводная сеть. Роутер при смене режима не перезагружается, Wi-Fi 5 ГГц пропадает примерно на полминуты.

- Одно радио. Одна сеть на весь диапазон, все каналы, до 160 МГц. Самая высокая скорость для одного устройства.
- Два радио, как 5G-1 и 5G-2 в стоке. Нижнее работает на каналах 36-64, верхнее от 149. Нижнему можно дать 160 МГц в его настройках, верхнему до 80 МГц. Удобно, когда устройств много.
- MLO. Одна сеть Wi-Fi 7 на оба радио. Устройства с Wi-Fi 7 и MLO держат связь сразу на двух каналах, остальные подключаются к одному из них как к обычной сети.

В режимах "два радио" и MLO каждое радио получает половину антенн. Поэтому одно устройство работает медленнее, чем в режиме одного радио. Цифры есть в [benchmarks.md](benchmarks.md).

С некоторыми кодами страны, среди них RU, прошивка радиомодуля выключает Wi-Fi 7, и точка работает как Wi-Fi 6. Блок "Режим 5 ГГц" об этом предупреждает, а кнопка рядом меняет код на US. Вместе с кодом меняются правила каналов и мощности.

Из консоли режим меняется так.

```
be7000-5g-split mode           # какой режим сейчас
be7000-5g-split mode split     # два радио
be7000-5g-split mode mlo       # MLO
be7000-5g-split mode single    # одно радио
```

## Настройки из стока

Если роутер пришёл со стока, где уже были настроены Wi-Fi и интернет, при первой загрузке Beam WRT сам возьмёт оттуда имена и пароли сетей Wi-Fi, подключение к интернету (PPPoE, DHCP или статический адрес) и адрес роутера. На странице Статус, Обзор видно, что перенесено, там же есть кнопка отмены.

Посмотреть, что лежит в стоке, ничего не меняя, можно так.

```
be7000-stock-import preview
```

Перенести настройки вручную и отменить перенос можно так.

```
be7000-stock-import apply
be7000-stock-import undo
```

Сток хранит настройки в зашифрованном контейнере. Скрипт открывает его только на чтение и с копии, так что при возврате сток найдёт их нетронутыми.

## Слоты и возврат на сток

На флеше два слота. Страница Система, Слоты показывает, что лежит в каждом, какой работает и какой загружается по умолчанию, и переключает на другой. Прошивка, которая загрузилась, сама делает свой слот основным, поэтому переключение действует насовсем. Перед переключением страница пишет, как потом вернуться со стока. Подробнее о загрузчике в [bootloader.md](bootloader.md).

## Аппаратная разгрузка

Разгрузка включается на странице Сеть, Аппаратная разгрузка. NAT и маршрутизацию может взять на себя сетевой процессор PPE, мост LAN-портов тоже. Функция проверена и работает, по умолчанию выключена. На странице подробно написано, что разгружается и с чем разгрузка не дружит, например с SQM.

Из консоли разгрузка включается так.

```
/usr/libexec/be7000-ppe status
/usr/libexec/be7000-ppe nat on        # сразу
/usr/libexec/be7000-ppe bridge on     # после перезагрузки
```

Сколько соединений сейчас идёт через PPE, показывает эта команда.

```
grep -c HW_OFFLOAD /proc/net/nf_conntrack
```

## Обновление

Роутер сам раз в сутки спрашивает у GitHub, вышла ли новая версия. Когда она есть, на странице Статус, Обзор появляется блок, а в верхней панели темы Nimbus кнопка. Проверку можно выключить на странице Система, Обновление сборки, там же новая версия ставится в один клик. Настройки сохраняются. Из консоли то же самое делается так.

```
be7000-update check     # есть ли новая версия
be7000-update apply     # скачать, проверить и поставить
```

Установленные вами пакеты после обновления сами ставятся заново под новое ядро, когда у роутера появится интернет. Если обновляетесь на 1.4 с 1.x, сначала прочитайте раздел об этом в начале docs/instruction/2-update.txt. Этот файл есть и в архиве релиза.
